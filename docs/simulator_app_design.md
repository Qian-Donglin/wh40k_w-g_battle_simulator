ここにシミュレーター全体でのアプリのデザインを記述する。

# 戦場の座標系

戦闘はすべてこの座標系の上で解決する。範囲攻撃の幾何判定・武器の射程判定・移動の前提となる。

## 次元と単位

- **2次元（平面）**。Z軸は持たない。
- **連続座標（浮動小数、メートル単位）**。グリッドは使わない。

> **グリッドを使わない理由**：範囲攻撃の較正が歪むため。基準密度 a=4m² に合わせて2mマスにすると、
> Blast Medium（半径2m）が中心＋隣接4マス＝5体を巻き込むことになり、RAWの3体から大きくずれる。
> 半径が小さいほど量子化誤差が効き、半径表（1m / 2m / 2.5m / 3.5m / 4.5m）を刻んだ意味が消える。
> またW&Gは元々メートル計測のシステム（射程16m / 48m / 150m、Speed 6＝6m）で、マス目前提のルールが存在しない。

> **Z軸を持たないことで捨てるもの**：飛行ユニット・高低差・高さ由来の遮蔽。
> 当面は平面上の距離だけで扱う割り切りとする。**【将来の課題】**

## キャラクターの占有

- **個体（PC・NPC）**：点として持つ。
- **Horde**：**円**として持つ。中心座標と半径を持ち、向き（facing）は持たない。

```
Horde半径 r_horde = √(N × a / π) = 1.128 × √N        ※ a = 4m²（基準密度）
```

| N | 半径 | 直径 |
|---|---|---|
| 5 | 2.5m | 5m |
| 20 | 5.0m | 10m |
| 100 | 11.3m | 23m |

- **向きを持たないので回転を管理しなくてよい。** Hordeに正面の概念を持たせると、扇形との重なり計算も配置UIも複雑になる。
- **Nが減ると自動的に縮む**ため、「削るほど巻き込みにくくなる」という性質がそのまま出る。
- 円×円の重なり判定には閉じた式があり計算が軽い。

> **性質**：`Blast Size X の円` と `N=X のHordeの円` は同じ大きさになる（どちらも同じ密度 a から導いているため）。
> 「Blast Largeは5人の群れと同じ大きさの爆発」と読める。

詳細な範囲攻撃の解決は `docs/area_attack_design.md` を参照。

# 画面1: シミュレーション画面

ゲームのシミュレーション画面。これは現在の`BattlSimulator.cs`の部分に相当する。

- この中で、右上か右下で、普段は隠れているメニューを置く。
- デザインは"三"のような形で、タップするとプルダウンorプルアップメニューが現れる。
- その中で、画面2: キャラクターロードや編集画面に遷移で切る。
- 左上に、画面3のタイトル画面に戻る機能をつける。

# 画面2: キャラクターのステータス画面

キャラクターのステータス画面。
ボタンによって、値を変更できるようにする編集モードへの相互切り替えも可能。

キャラ名と、既に設定したステータスと、持っている武器や弾薬を見せることができるUIを持つ。

# 画面3: タイトル画面

シミュレーターのタイトル画面。

- 画面1のシミュレーター画面
- 画面4の装備画面
//- 画面5のキャラ特性、装備特性編集画面
//- 画面6のキャラクター編集画面

にそれぞれ遷移するボタンを、縦に並べる。

タイトルはこのプロジェクトの名前としてください。

# 画面4: 装備画面

装備(近距離武器、遠距離武器、弾薬、防具、その他装備)などについて、検索、編集、追加、削除する画面。

すべての武器は、特性を持つ。(特性のない武器も存在する)

武器の持つべきステータスは、`docs/equipments/weapon.md`を参考にする。

UIは、上部検索できるバーと、下側に検索して出てきた武器をList状に並べたものを持つ。各行の要素は、以下のものを含む。

- 装備の名前
- ダメージと、ダイスによる追加ダメージ。10+1EDのように記述する。
    - 存在しない装備は"-"で表示する。
    - 防具の場合は、例外的に"AP X"と表示。(Xは防具が提供するアーマー値)
- 装備と持つ特性。これはラベルのような表記で、横に並べる、見切れていても、その中で横スクロールできるなら構わない。
- 遠距離武器限定で、"2/10"のようにSalvoとArmoの値を追加する。

装備は、追加、削除、編集ができる。

編集UIは、値の編集は1行目に特徴以外の値のすべてを編集できるようなテキストボックスを並べる。
2行目には装備特性を並べる。
編集ウィンドウは縦軸を固定する必要はない。
編集ウィンドウの外を押すとキャンセルボタンと同じようにメインウィンドウを消したい。
