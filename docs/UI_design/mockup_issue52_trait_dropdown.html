ISSUE #52 PART OF #3 依存: #47 V1.0 — APPROVED

装備編集ダイアログ: 特性入力をドロップダウン選択式にする

現状、装備編集ダイアログ（画面4）の特性欄は Brutal, Piercing(2), StatusEffect:OnFire のようなカンマ区切り文字列の手打ちになっており、 誤字や特性名を覚える負担がある（#14指摘）。本ドキュメントは特性の選択をドロップダウン（カテゴリ別チェックリスト）方式に置き換える提案。 カテゴリ分類・アイコンは #50 承認済みのものをそのまま流用、配色トークンは #47 承認済みのものを使用。 2026-08-09 レビューで承認済み。Unityへの反映は #16 でまとめて行う（このissue単体では実装しない）。

01 — 現状の課題

編集ダイアログの2行目（特性欄）は1本のテキストボックスで、EquipmentEditDialog.cs の ParseTraits() がカンマ区切りをパースしている。実装済みの特性は29種類あり、綴りや大文字小文字を間違えると保存時に警告が出るだけで静かに無視される（Debug.LogWarning）。

特性
課題：特性名は英語表記かつ29種類あり暗記できない。ratingを持つ特性かどうか・括弧の書式（全角/半角、スペース有無）も自己判断が必要で入力ミスが起きやすい。

02 — 提案：特性エディタ（下のデモは実際に操作できます）

同じ武器（Master-Crafted Bolter）の特性欄を新UIに置き換えたイメージ。「＋ 特性を追加」を押すとカテゴリ別チェックリストが開き、チェックした特性がチップとして欄に並ぶ。rating(X)を持つ特性はチップ内に数値入力欄が現れる。

特性
保存時の内部表現（TraitsToString と同一形式・参考表示） RapidFire(1), Piercing(2)
互換性：チップ操作の結果は既存の TraitEntry（trait / rating / statusEffectName）にそのまま対応し、保存時のシリアライズ形式（Name(rating) / StatusEffect:Name(rating)）は現行と変更しない。Unity実装時は ParseTraits() によるカンマ区切りパースをやめ、チップの状態から直接 List<TraitEntry> を組み立てる想定。

03 — カテゴリ分類とアイコン（#50を流用）

#50で確定した5カテゴリ・アイコンをそのまま使用する。新規追加のカテゴリ・アイコンはない。

カテゴリ選択できる特性
攻撃力・貫通 Brutal / Piercing(X) / Melta(X) / Rending(X) / Concussive(X) / Power(X) / Force / Warp Weapon / Waaagh!
命中・範囲 Blast(X) / Barrage / Flamer / Spread / Sniper(X) / Sonic
運用・利便 Assault / Pistol / Rapid Fire(X) / Reliable / Steadfast / Silent / Parry / Psyniscience / Deny the Witch
状態異常 Toxic（固定・rating無し） / StatusEffect（名称自由入力＋rating、複数追加可）
要件・リスク Heavy(X) / Unwieldy(X) / Supercharge

(X) = rating値（数値）を持つ特性。全29種の内訳は WeaponTrait.cs のenumおよび docs/equipments/weapon.md と一致させている。

04 — レーティング(X)を持つ特性の入力

チェックすると、そのチップに数値入力欄（<input type="number"> 相当）が付く。デフォルト値は 1。rating不要な特性（Brutal・Assaultなど）にはこの欄を出さない。

Piercing Heavy
決定：ratingの最小値・最大値のバリデーションはここでは設けない。入力可能範囲の制限が必要かはUnity実装(#16)側で判断する。

05 — StatusEffect（状態異常）の入力

StatusEffectは他の特性と違い固定の名称リストを持たない（On Fire、Poisonなど自由）ため、専用の追加導線を用意する。特性パネルの「状態異常」カテゴリ内、Toxicチェックボックスの下に 「＋ 状態異常を追加」 ボタンを置き、押すたびに名称入力＋rating入力のチップが1つ増える（複数の状態異常を同時付与する武器を想定）。

決定：状態異常名は自由入力のままとし、既存データからのサジェスト（datalist等）は導入しない。現行データセットにStatusEffectの実例がなく判断材料が薄いため、実データが増えてから必要に応じて別issueで検討する。

06 — Before / After

Before（現行）

自由入力。特性名・括弧書式を手で正確に書く必要がある。

After（提案）

Rapid Fire Piercing

選択式なので綴りミスが起きない。ratingは専用の数値欄で入力する。

07 — インタラクション仕様（案・要レビュー）

  • 「特性を追加」を押すとカテゴリ別チェックリストパネルが開く（#51のフィルタパネルと同じ開閉挙動：外側クリックで閉じる）。
  • 非StatusEffect特性はチェックボックスのON/OFFがそのままチップの追加/削除に対応する（1特性につき1エントリのみ、重複不可）。
  • チップ側の「×」ボタンで削除すると、パネル側の対応するチェックボックスも自動的に外れる（相互同期）。
  • StatusEffectのみ「＋ 状態異常を追加」ボタンで何個でも追加できる（同名重複のチェックは行わない・要レビュー）。
  • rating入力欄は特性チェックと同時にデフォルト値1で生成され、以後チップ内で自由に編集できる。
  • チップが1つも無い状態（特性なしの武器）も許容する。

08 — スコープ外事項（決定）

  1. 防具(Armour)の特性欄 — 現行 ArmourData.traits は List<string> の自由入力（例: "Ablative"）で、武器側の29種 WeaponTrait enumとは別管理になっている（weapon.md 上は Power(X) が「アーマー専用特性」とされているが、実装はまだ enum 化されていない）。本issueのドロップダウン化は武器・弾薬（Melee/Ranged/Ammo）の特性欄が対象で、防具欄は現状の自由入力のまま変更しない（対象外で確定）。防具側をどう扱うかは別issue化を検討。
  2. 未知の特性名の扱い — ドロップダウン化により基本的に発生しなくなるが、既存データに手打ちの誤字が残っている場合の警告UIは #56 の管轄とする（本issueでは扱わない）。
  3. rating値のバリデーション — 04節の通りバリデーションは設けず、実装(#16)側の判断とする（決定）。
