ISSUE #53 PART OF #3 依存: #47 V1.0 — APPROVED

装備編集ダイアログ: フィールドラベルを分かりやすくする

現状、編集ダイアログ（画面4）の数値フィールドは ED / AP / AR のような略語ラベルのみで、 初見では何を入れるか分からない（#14指摘）。本ドキュメントは各ラベルに ⓘ アイコンを添え、ホバーで正式名称・説明を表示するツールチップを提案する。 配色トークンは #47 承認済みのものを使用。ラベル文字自体（Dmg/ED/AP/Salvo/Mag/Uses/AR）は変更せず、 射程系ラベルのみ Melee=「射程」/ Ranged=「Range」の表記ゆれを「射程」に統一する（04節）。 2026-08-09 レビューで承認済み。Unityへの反映は #16 でまとめて行う（このissue単体では実装しない）。

01 — 現状の課題

EquipmentEditDialog.cs の AddCompactField() がラベルをそのままテキストで描画しているだけで、説明や単位の補足が一切ない。4種の装備すべてでラベルは略語（Dmg/ED/AP/Salvo/Mag/Uses/AR）のみ。

Melee（近接武器）
Ranged（遠距離武器）
Ammo（弾薬）
Armour（防具）
課題：ED・AP・AR は W&G のルール用語としては存在するが、初見のユーザーには意味も入力単位も分からない。Mag / Uses / Salvo も同様。加えて「射程」を表す項目が Melee=日本語「射程」、Ranged=英語「Range」と表記が割れており、同じ概念であることが伝わりにくい。

02 — 提案：ⓘ アイコン + ホバーツールチップ（下のⓘに実際にカーソルを合わせてみてください）

各略語ラベルの右側に小さな ⓘ を追加。ホバー（またはキーボードフォーカス）すると、正式名称・日本語説明・単位の補足がツールチップで表示される。ラベル文字自体は変更しないため、既存の狭い列幅（55〜70px）でもレイアウト崩れが起きない。列幅・余白の再設計は #57 の管轄とし、本issueでは扱わない。

決定：ⓘアイコンはマウスホバー / キーボードフォーカスで表示する方式を採用。Unity実装(#16)では EventTrigger（PointerEnter/PointerExit）+ 簡易ツールチップUIで実現する想定。ゲームパッド操作等の代替導線は#16側で検討。

04 — 射程ラベルの統一（要レビュー）

現行コードでは近接武器の射程フィールドが日本語「射程」、遠距離武器が英語「Range」になっており、同じ「武器が届く距離」という概念なのに表記が割れている。本issueで「射程」に統一する案を提示する。

Before（現行）

同じ「距離」の概念なのに日本語／英語で表記が異なり、初見だと同種のフィールドと気づきにくい。

After（提案）

両方とも「射程」に統一。差異（半径 vs 射程距離／Short・Long判定の有無）はツールチップで説明する。

決定：「射程」に統一する。ラベル文字列の変更は EquipmentEditDialog.cs の BuildFields() 内 AddCompactField(row1, "Range", ...) を "射程" に変更するだけで済み、保存データ（range フィールド名など）には影響しない。実装は#16でまとめて行う。

05 — スコープ外事項（決定）

  1. フィールド間の余白・列幅の再設計 — #57の管轄。本issueではラベル文言・ツールチップの追加のみを扱い、既存の列幅・間隔は変更しない。
  2. 数値フォーマットの入力検証 — #55の管轄。ツールチップは説明のみで、バリデーションは行わない。
  3. 必須項目チェック — #54の管轄。
  4. 特性欄（Traits）のラベル — 「特性」は既に平易な日本語のため対象外。特性の選択方式自体は#52で決定済み。
  5. 防具の特性欄（自由入力） — #52同様、本issueでも対象外（変更なし）。

06 — レビュー結果（決定事項）

  1. ⓘアイコン + ホバーツールチップ方式を採用 — ラベル文字は変えず、ⓘアイコンのホバー/フォーカスで正式名称・説明を表示する。2行常時表示ラベルや正式名称への置き換えは、列幅崩れ・#57との競合を避けるため不採用。
  2. 射程ラベルの統一（04節） — Melee/Rangedとも「射程」に統一する。
  3. ツールチップ文言 — 03節の対応表の文言案で確定。
